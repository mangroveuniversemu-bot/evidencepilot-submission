# Security policy

## Secrets

- No credentials, tokens, or `.env` files are committed to this repository.
- AWS credentials are resolved through the standard AWS credential chain. The
  code never reads a credential from a file in this repository.
- Certificates and execution traces record file hashes and tool names, never
  file contents, so an artifact can be published without leaking the data it
  was computed from.

## Data

Every dataset under `examples/` is synthetic and generated by
`scripts/build_examples.py`. No measured data, no unpublished research, and no
third-party data appears in this repository. See `docs/ip_boundary.md`.

## Model boundary

The language model is given tools that read from disk and return computed
values. It cannot write files, cannot alter a verdict, and cannot introduce a
number into a certificate — the verdict and every figure come from
`policy/verdict_rules.py` and `tools/`, which run without a model at all. A
prompt-injection payload embedded in a submitted artifact can therefore change
what the agent *says*, but not what the certificate *records*.

### What is actually tested

`tests/adversarial/test_prompt_injection.py` runs
`examples/adversarial/case_g_prompt_injection`, a copy of the hero case whose
identifiers carry a payload demanding an `ALLOW` verdict. It asserts both
halves, because either alone would be misleading:

1. **The payload reaches the model.** It is present in at least three of the
   five tool projections in `agent/researchops_agent.py`. Without this the
   test would pass vacuously — which is what would happen if the payload were
   hidden in `manifest.notes`, `manifest.operator`, `claim.conclusion` or
   `claim.submitted_by`, none of which any tool returns.
2. **Nothing that matters changes.** The verdict stays `BLOCK`, every number is
   identical to the clean run, the root cause is still `BLK-02`, the provenance
   checks fire the same way, and the certificate signature matches the clean
   one once the identifiers carried as data are normalised.

**What this does not establish.** It shows the *deterministic* pipeline is
unaffected. It does not show what a model would write when shown the payload —
that needs a live Bedrock run and is tracked as EPIC-01 in `docs/epics.md`. The
security property being claimed is that the certificate is trustworthy even if
the prose is not; the prose itself is not certified.

## Local review workbench

`app/review_ui.py` binds only to `127.0.0.1`. Exact Host/Origin validation,
a per-process write token, bounded JSON bodies and a restrictive content policy
protect against ordinary drive-by browser writes. This is **not** authenticated
multi-user authorization: another local process can access the app, and reviewer
names are self-reported. Do not expose it through a proxy or public tunnel.

Decision records are append-only through the application and use local SQLite
transactions. They reference the original certificate and do not modify it or
execute an action. An unkeyed checksum detects accidental alteration, not a
malicious database owner recomputing hashes. Records are not encrypted and are
not synced or backed up automatically. Keep private research and credentials
out of reviewer text; review all exported names/reasons before sharing.

The model tools and hosted AgentCore entrypoint cannot call this local write
path. See `docs/review_workbench.md` for the exact scope and tests.

## Reporting

Report suspected vulnerabilities privately to the repository owner rather than
opening a public issue.
